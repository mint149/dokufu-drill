# ロードマップ

## 最終目標

MIDI ファイルを読み込み、曲の全体または指定した区間を、指定した BPM で正確に弾けたかを判定する。
そのために、和音の判定と、数分間を通した判定ができるようにする。

## 実現性の判断

今の構成（静的サイト＋ブラウザの標準機能、GitHub Pages で公開）で実現できる。サーバーは不要。
ただし、次の 3 点は今の作りのままでは対応できないので、段階的に変える。

| 項目 | 判断 |
|---|---|
| 公開（GitHub Pages、HTTPS） | そのまま使える |
| 電子ピアノ入力（Web MIDI） | そのまま使える。入力イベントに付く時刻（`MIDIMessageEvent.timeStamp`）で、タイミング判定に十分な精度がある |
| MIDI ファイルの読み込み | 自前のパーサー（200 行程度）か、@tonejs/midi などのライブラリで対応できる |
| 判定の計算量 | 数分の曲でも音符は数千個程度。スマホでも問題ない |
| 1 ファイル構成 | **変更が必要**。Vite でファイルを分け、判定ロジックに単体テストを書く（v0.1） |
| 楽譜の表示 | **変更が必要**。手描き SVG は単音 1 つしか描けない。リズム・和音・連桁・複数声部には VexFlow などが必要（v0.3） |
| スマホの音の遅れ | **対策が必要**。Android は音が聞こえるまで数十〜100ms 以上遅れることがある。補正の仕組みを作る（v0.3） |

### MIDI ファイルは「楽譜」ではない

MIDI ファイルには「どの高さの音を、いつ、どれだけ鳴らすか」しか入っていない。
♯ と ♭ のどちらで書くか、右手と左手の分け方、声部、連桁、タイの情報はない。
演奏を録音したファイルは、音の長さもそろっていない。

- **判定**には MIDI ファイルで十分。
- **楽譜の表示**は、楽譜ソフト（MuseScore など）から書き出した MIDI ならかなり読めるが、演奏録音の MIDI だと難しい。
- 確実に読める楽譜を出したい場合は、MusicXML にも対応し、表示を OpenSheetMusicDisplay に任せる。

### タイミングの精度

- 鍵盤を押した時刻は電子ピアノからの信号に付く時刻を使うので正確。
- ずれるのはスマホから出るメトロノームの音。対策は次の 2 つ。
  - 「クリックに合わせて叩く」補正で遅れを測り、差し引く。
  - メトロノームを P-225 本体で鳴らす（Web MIDI の出力で、時刻を指定して送る）。遅れがほぼなくなるが、P-225 で使える音色の確認が必要。

## 段階

1 段階を 1 リリース（`/next/` で試してからタグを付ける）の大きさにする。

### v0.1　土台づくり（見た目は変わらない）

- Vite を導入し、判定・楽譜描画・MIDI・音声などをファイルに分ける。
- 判定ロジックを画面の処理から切り離し、Vitest で単体テストを書く。
- 公開用スクリプトを、タグごとにビルドする形に直す（ビルド工程のない v0.0.1 もそのまま公開し続ける）。

### v0.2　和音の判定

- 2〜3 音の和音を出題し、五線に重ねて描く（2 度の音は左右にずらす）。
- 短い時間（例：80ms）に押された音を 1 つの和音としてまとめ、出題された音がそろっているかを判定する。
- 余分な音・足りない音がどれだったかを表示する。
- 画面の鍵盤では「複数の鍵盤を選んでから決定」で答える。
- ここで作る「和音をまとめて判定する処理」が、最終目標の判定の中心になる。

### v0.3　リズムとタイミング

- Web Audio で先の時刻に予約して鳴らすメトロノーム。
- 音の遅れの補正機能。P-225 とスマホの組み合わせで実際の遅れを測る。
- 楽譜描画を VexFlow に切り替える。
- 1〜2 小節の短いフレーズを指定 BPM で出題し、「早い／遅い ○ms」を判定する。
- 演奏中に画面が消えないよう Wake Lock を使う。

### v0.4　MIDI ファイルの読み込み

- ファイルを読み込み、トラックを選ぶ（右手だけ・左手だけなど）。
- 拍にそろえて（クオンタイズして）楽譜を描く。
- 読み込んだ曲を IndexedDB に保存して一覧にする（localStorage では容量が足りない）。
- 曲を合成音で鳴らして聴ける。

### v0.5　区間を指定した通し判定（最終目標の最小形）

- 小節の範囲を選び、カウントのあとに指定 BPM で通して弾く。
- 演奏位置に合わせて楽譜をスクロールし、カーソルを出す。
- 正しく弾いた音・弾き間違えた音・抜けた音・余分な音と、各音のタイミングのずれを判定する。
- 結果画面で、小節ごとの正確さと、ずれの傾向（走りがち・もたりがち）を見る。
- 苦手な区間だけを繰り返す。

### v1.0 以降　仕上げ

- テンポに追従する判定（多少のテンポの揺れは許し、音の並びの正しさを見る）。
- 少しずつ BPM を上げる練習、曲ごとの成績の記録。
- MusicXML への対応。
- 音の長さ（離すタイミング）とペダルの判定。
- PWA 化（オフラインでも起動できる）。

## 早めに実機で確かめること

1. P-225 と Android の組み合わせで、入力時刻の精度とスマホの音の遅れ（v0.3 の最初）。
2. P-225 に MIDI で音を送って鳴らせるか、使える音色は何か。
3. 数分の楽譜を約 400px のスマホ画面で読めるか（横向き・タブレットも含めて）。

## 決めておくこと（v0.4 までに）

- 使いたい曲の入手方法：楽譜ソフトで作った・書き出したファイルか、演奏録音の MIDI か。楽譜表示の方針がこれで決まる。
- 判定の厳しさ：BPM を厳密に守るか、テンポの揺れをある程度許すか。まず厳密な判定を作り、追従する判定は v1.0 以降に回す。
